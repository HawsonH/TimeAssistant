# 时屿 UI 与功能优化方向

评估日期: 2026 年 10 月 13 日  
适用基线: Android 1.0，versionCode 1

2026-10-15 已开始按批准计划实施，本文保留原始问题与验收目标。当前已实现/部分/待实现状态见《时屿优化实施进度》，不能将下文历史现状当作新版结论。

## 1 建议结论

先把现有功能变得容易发现、容易理解、可验证可靠，再增加功能数量。建议保留聊天、安排、专注三个主入口，优先完成任务快捷操作、专注状态表达、AI 数据授权和提醒诊断。

首批新功能建议选择搜索筛选与周视图，后续再做专注复盘、任务模板和桌面快速记录。云账号、多方协作和系统日历双向同步暂不进入首轮范围。

本文是优化方案，不代表已经修改 UI 或新增功能。源码已具备的周期日程、主动 AI、偏好学习、局域网同步和数据导入导出，属于改进现有能力，不应作为从零新增重复开发。

## 2 现状与目标

### 2.1 保留的基础

三个主入口职责明确，手动操作不强依赖 AI。AI 操作先确认、系统日历只读忙碌区间、主动整理不自动执行变更、核心仓库共享和专注幂等结算，都是应保留的设计边界。

已经存在 ViewBinding、Controller、ViewModel 和语义主题资源，可在当前 Java 与 XML 技术栈中持续改进，无需先迁移到全新 UI 框架。

### 2.2 优化目标

- 用户首次进入后，不看手册也能找到新建、完成、编辑和返回今天。
- 用户能区分待办、日程、未确定时间、倒计时和专注记录。
- AI 每一次修改都能明确看到对象、范围、变化和执行状态。
- 权限关闭、服务失败、后台延迟和同步冲突有可处理的反馈。
- 每个新功能都有可验收的状态、数据边界与回归测试。

本文中的指标是未来验收目标，不是当前实测成绩。

## 4 全局 UI 规范

### 4.1 信息层级

页面标题采用紧凑尺度，统计摘要作为辅助信息，不占据主要操作空间。列表、表单和设置强调扫描效率，不把每个分组都包成大卡片。

建议采用 4dp 或 8dp 的间距体系。常用正文约 14-16sp，辅助文字约 12-14sp，标题按页面职责设置；最终以系统字体缩放和实机阅读结果为准。

在各主题下保留中性背景与清楚的正文颜色，用品牌色突出主操作，用独立语义色表达成功、警告和错误。不让同一紫色同时承担所有状态。

### 4.2 控件与反馈

- 完成使用复选控件，工具操作使用已有图标与更多菜单。
- 模式切换使用分段控件，开关使用 Switch，时间使用时间选择器。
- 保存、删除、生成方案等命令保留明确文字。
- 可触控目标按至少 48dp 的验收标准处理，小图标可以小于目标区。
- 删除后用可撤销反馈处理单项操作，危险清空仍保留二次确认。
- 不以颜色独立表达状态，同时提供文字或图标及无障碍描述。

**依据和边界:** 当前已有不少 48dp 控件与无障碍动作，不是整页不合格；需要重点检查动态生成的 38-44dp 操作和小字号状态。已有 edge-to-edge 与 Insets 处理应保留，增加键盘、横屏和系统导航回归测试，不要重复接入。

### 4.3 状态覆盖

每个页面至少设计空数据、加载中、成功、失败、权限关闭和离线场景。空状态直接提供业务操作，例如新增待办；不依靠长段界面使用说明代替明确控件。

屏幕宽度、长标题和字体缩放不得改变控件的基本交互位置。避免固定高度截断多行文字，关键操作不能因长标题消失。

## 5 安排页改造

### 5.1 当前问题

普通卡片点击只读、左滑才有编辑和完成，操作可发现性不足。日程、待办和注意有不同日期规则；浏览未来日期后，新建表单没有自动继承该日期。注意页还有三组事项，缺少直接可见的处理动作。

现有月历适合选日期，不适合比较一周负荷。缺少覆盖所有历史任务的搜索入口。

### 5.2 建议结构

1. 顶部显示明确日期、前后一天箭头、返回今天和日历入口。
2. 保留日程、待办、注意切换，注意附待处理数量。
3. 普通任务行增加可见完成控件与更多菜单，左滑保留为快捷方式。
4. 注意事项直接提供对应动作: 重新安排、确认结果、补全时间。
5. 加号继续使用图标，必要时在选择后进入待办或日程创建，不强制新增底部主入口。

建议的日程任务行信息顺序为时间、标题、状态、少量备注。重要状态优先于装饰性标签，长标题允许两行后在详情完整阅读。

### 5.3 编辑体验

合并任务创建和编辑的基础表单，按是否需要具体时间展示差异。基础字段、时间、重复规则、提醒、危险操作分区，但不要让用户为查看三个常用字段反复切换。

日期使用正在查看的日期作为初始值，同时在保存前明确展示；如果产品选择不带入，也必须有清晰的目标日期确认。时间选择中提供预设时长及根据开始时间计算结束时间的能力。

对跨日安排和结束早于开始的输入，给出具体错误，不静默裁剪或纠正。周期修改继续保留三种作用范围，并展示影响的首个日期和未来实例预览。

### 5.4 验收

- 不使用滑动时，仍能在任务行完成和打开编辑。
- 从未来日期新建的任务，保存日期与表单显示一致。
- 普通待办不会因设置倒计时占用时间线。
- 周期规则、实例和例外保持当前稳定 ID 与数据语义。
- 320dp 宽度、长中文标题、较大字体下，日期和关键操作可达。
- 左滑、页面横向切换、列表纵向滚动之间无明显手势冲突。

## 6 聊天页改造

### 6.1 当前问题

AI 提案嵌套多层卡片和重复确认按钮，步骤多时滚动成本高。修改描述未必清楚展示前后差异，历史只读与当前会话也容易混淆。服务是否配置、是否联网可用应分开表达。

### 6.2 建议结构

顶部保留时屿身份、历史日期与服务状态入口。未配置 AI 时仍允许用户进入手动安排和专注，不把整页变成配置广告。

操作提案改为一个平整的待确认区域，按任务、偏好、系统跳转分组。每条操作显示对象和变化，修改时间时突出原时间与新时间；删除和系列级操作采用危险标记与影响范围。

多项提案可选择待执行项，再使用统一执行栏。逐项确认仍保留，不让批量确认越过必要的高风险确认。

读取来源放在消息后可折叠区域。附件显示名称、类型、大小与移除图标；在服务不支持时给出具体原因和可重试动作。

### 6.3 验收

- 创建、修改、删除和外部跳转的视觉状态不同。
- 已成功步骤不可被重试再次执行；失败、取消、未执行不混为一类。
- 继续对话替换方案时，明确标记旧方案失效，保留审计历史。
- 历史页面有明显只读状态，并能直接返回当前会话。
- 系统日历预填只显示已打开编辑器，不误报事件已经保存。
- AI 学习、主动请求与手动聊天的数据请求范围分别说明。

## 7 专注页改造

### 7.1 当前问题

模式切换主要依赖圆环横滑。正计时是有限时长显示，却可能被理解为无限计时；运行中只有取消与结束，且取消不留记录，含义需要更明确。任务名区域单行固定高度可能使长名称不完整。

### 7.2 建议结构

圆环仍为主视觉，但在上方增加专注、短休、长休分段控件。统计摘要缩为一行，将当前模式、当前任务、目标时长与主要操作放在第一屏。

准备态显示开始；运行态突出结束记录，取消本轮作为次要操作。点击取消时保留“不计入记录”的确认。若增加暂停继续，按新功能单独设计，不把准备态的 PAUSED 模型状态当作现有暂停能力。

模式和运行状态都使用文字与图标反馈，不能只靠环的颜色变化。任务名称允许适度换行或提供完整详情，不让圆环挤掉底部操作。

结束反馈优先区分本轮完成和任务完成。自动衔接前显示下一阶段及是否会自动开始，避免“开关开启但仍在等反馈”造成预期错位。

### 7.3 验收

- 用户不依赖手势说明即可找到三种模式。
- 取消不记账、提前结束记已用时、自然完成记完整轮次的口径一致。
- 有限正计时明确显示目标上限。
- 同一会话的前台回调、服务和闹钟只产生一条完成记录。
- 进入后台、锁屏、返回后时间连续，任务关联与统计一致。
- 隐私模式下锁屏通知的标题、正文、副标题、自定义视图均不暴露任务名。

## 8 设置页改造

### 8.1 建议分组

保留现有类别的数据边界，但优先用纵向列表概览和清楚的二级页面减少横向类别的隐藏。可采用以下信息架构:

| 分组 | 内容 |
| --- | --- |
| 外观 | 配色、跟随系统深浅色、字体适配 |
| AI 与隐私 | 服务配置、测试、错误日志、学习开关、读取范围 |
| 时间与提醒 | 可用时段、工作时段、排除时段、通知状态 |
| 主动整理 | 总开关、节奏、触发条件、额度、免打扰 |
| 连接 | 系统日历、设备配对与同步状态 |
| 数据 | 导入、导出、恢复范围、清理 |

这是建议中的新分组，不是当前手册的导航路径。是否移动设备同步入口需要同步更新用户手册与深链。

### 8.2 保存方式

当前既有选择后立即生效的主题与开关，也有需要点击保存的 AI、时间、专注表单。应统一表达哪些已保存、哪些仍是草稿，离开未保存表单时提供处理选项。

时间段改用时间选择器和可添加删除的时段列表，避免用户手打逗号字符串。数值越界应提示可用范围，不静默截断为另一数值。

### 8.3 提醒诊断

新增诊断区域，展示应用提醒开关、系统通知权限、通知渠道、锁屏内容显示及后台限制，并提供对应设置跳转。

诊断只能陈述可检测状态，不把“权限已授予”显示为“保证不会漏提醒”。提供一次短时测试提醒与结果记录，而不是声称可以绕过所有厂商限制。

## 9 推荐新增功能

### 9.1 搜索筛选与批量处理

**价值:** 当任务积累后，按日期翻找或只看今天无法快速定位历史事项。

最小范围是标题和备注搜索，按状态、日期范围、是否排期过滤。项目与标签字段已有模型基础，可先提供筛选和编辑入口，不立即做复杂项目中心。

批量完成和移动日期需展示影响数量。批量删除与周期系列变更要单独确认，不允许隐藏危险操作。

实现建议复用仓库与 Room 查询能力，分页或增量加载；避免先在主线程读取和重建全部卡片。

### 9.2 周视图与冲突提示

**价值:** 月历负责选日期，周视图负责比较一周时间占用和空闲。

首版以只读时间网格、日期切换、点击编辑为主，先不加入高风险拖拽排程。显示日程与系统日历忙碌区间，但系统忙碌条不展示未获授权的事件标题。

冲突展示涵盖应用任务互相重叠、禁排时段与授权忙碌区间，提示数据来源。主动修改仍遵守用户确认与锁定约束。

### 9.3 专注复盘和计划实际对比

**价值:** 当前已有记录和今日统计，可扩展为能解释时间使用情况的周月复盘。

指标包括总专注时长、完整番茄数、提前结束时长、中断次数与任务实际投入。取消本轮和休息不混入专注时长；删除记录后统计口径保持一致。

先做本地确定性统计，再提供用户主动触发的 AI 总结。不得在未告知时把完整历史自动发送给模型。

### 9.4 任务模板和项目标签入口

**价值:** 缩短重复录入，利用已有项目、标签、优先级和子任务字段。

模板保存标题、备注、预估时长和子任务结构，不固定复制历史完成状态或旧任务 ID。周期日程负责按规律重复，模板负责用户主动复用，两者不混淆。

首版采用轻量项目标签列表、任务筛选和模板创建，不扩张为多人协作平台。

### 9.5 快速记录与小组件

增加系统分享入口或桌面快捷方式，将文本记录为待办；小组件可展示下一项日程及开始专注入口。

必须设计锁屏与桌面隐私选项，禁止默认展示敏感任务备注。进程重建、已删除任务和权限关闭时深链应安全降级。

### 9.6 暂停继续与无限正计时

这不是仅增加按钮: 需要定义暂停是否计入时长、通知如何展示、进程重建如何恢复、跨设备同步如何处理，以及结束后如何记账。

无限正计时还需定义目标时长为空、记录上限、跨日归属和退出恢复。建议在后台结算和统计口径稳定后实施，与当前有限正计时明确区分。

### 9.7 加密备份与同步

备份优先提供用户口令加密、恢复预检、内容范围和密码丢失说明。不能仅将 JSON 改扩展名就称为加密。

同步升级需要真实的认证加密、会话或设备密钥管理、重放防护与协议版本兼容。保留 API Key 本机独立原则。涉及安全协议时采用成熟标准与库，不自创密码算法。

## 10 暂不优先的方向

**云账号和跨网同步:** 带来账户、安全、服务运维、删除请求与持续成本，先验证局域网同步和备份需求。

**完整系统日历双向同步:** 涉及事件 ID 映射、删除冲突、重复规则和权限，需要独立设计，不只是将“打开日历”改为自动写入。

**后台自动接受 AI 变更:** 与当前确认式产品边界冲突，容易造成误改和信任问题；不建议作为默认方向。

**一次性 UI 框架重写:** 会扩大验证范围，不能替代当前状态管理、隐私和操作可发现性的问题修复。

## 11 实施顺序

### 阶段一 形成可信基线

完成 R01-R05，获得当前构建报告和设备测试结果；明确 AI 学习请求、锁屏内容、同步未加密及导出范围。为任务和专注关键状态建立回归用例。

退出条件: 不用历史报告替代当前验收，后台专注不重复记账，隐私边界能从设置中查到。

### 阶段二 改进高频 UI

完成 U01-U06，同时逐步建立 U07 的颜色、触控和字号规范。优先安排页，再专注页与聊天确认卡，最后设置结构调整。

退出条件: 不依赖手势也能完成核心任务，保存与即时生效的状态清楚，小屏大字号不隐藏关键操作。

### 阶段三 扩展检索与规划

完成 F01 与 F02，用真实内测数据观察搜索、筛选和周视图的价值。周期规则与单次例外保持兼容，拒绝在 UI 重构中顺带更换所有持久化结构。

退出条件: 历史任务可查、一周安排可比较、没有重复任务或周期历史丢失。

### 阶段四 按反馈选择扩展

根据用户实际使用选择 F03-F07，不要求同时开发。每项先定义数据迁移、恢复路径、隐私范围和测试方案，再评估工作量。

## 12 工程落地建议

### 12.1 按职责渐进拆分

`TimeAssistantActivity.java` 当前为 8149 行，已有 PageController 和 ViewModel，但 Controller 主要管理 binding 与状态。建议逐步迁移任务编辑、提案显示、专注交互、同步设置协调到对应模块。

保留 Activity 负责导航、权限和生命周期桥接。业务写操作继续经过仓库和用例，不让页面分别维护可写全量快照。

不要为了缩短文件而拆出大量无语义工具类。按一次真实改造的职责边界拆分，并通过现有行为测试保护结果。

### 12.2 提升列表与渲染策略

现有安排页使用 ScrollView 和动态 LinearLayout。数据量增加后，建议迁移为 RecyclerView 配合差分更新，保持稳定 ID、滚动位置和倒计时局部刷新。

这是性能风险与结构改进建议，本次没有进行基准测量，不能声称已经存在确定的帧率下降。

### 12.3 配置与协议

远程 AI 服务优先限制 HTTPS。当前 Manifest 全局允许明文流量，应复核真实用途并收紧网络配置；原始 TCP 同步的安全问题需在协议层独立解决，不能认为一个网络配置开关会让同步变成加密。

同步源码已支持周期组、周期例外和提醒事件合并，而现有协议说明主要展示任务、聊天和专注等基本字段。应补全协议字段与删除标记文档，并为桌面实现增加兼容测试。

JSON 导入增加预检摘要和范围说明，尤其说明本地智能库不在普通备份中。全量快照撤销要测试与后台或同步并发写入是否互相覆盖，后续可改成实体级撤销记录。

### 12.4 测试分层

保留纯模型、提案解析和协议单元测试。针对任务编辑、权限、聊天确认、日期上下文增加 UI 测试；后台服务、幂等结算、数据库迁移与设备同步使用仪器或集成测试。

已有仪器测试源码不等于已执行。优先解决安装签名错误，建立不触碰真实用户数据的测试安装方案。

## 13 验收矩阵

| 维度 | 建议组合 | 检查内容 |
| --- | --- | --- |
| 屏幕 | 320dp、360dp、412dp、横屏 | 圆环、长任务名、表单、底部操作不裁切 |
| 字体 | 默认、1.3 倍、2 倍 | 文本可读，关键按钮可达 |
| 主题 | 四种配色；深色为新增后验证 | 文字和状态对比，不依赖颜色传意 |
| 导航 | 手势导航、三键导航、键盘弹起 | Insets 正确，输入区不被遮挡 |
| 权限 | 允许、拒绝、运行后撤销 | 通知、麦克风、日历状态准确 |
| 生命周期 | 旋转、后台、锁屏、进程重建 | 草稿、计时、待确认操作不异常丢失 |
| 网络 | 正常、断网、超时、服务错误 | 重试不重复执行，配对失败可恢复 |
| 数据 | 空数据、长标题、大量任务、旧备份 | 查询、迁移、列表和导入语义正确 |
| 多设备 | 并发编辑、删除、时钟差异 | 版本合并与冲突状态可解释 |

真机验证建议至少包含一种接近原生系统和一种厂商系统，具体机型按团队设备确定。没有设备结果前，不宣称覆盖全部厂商。
