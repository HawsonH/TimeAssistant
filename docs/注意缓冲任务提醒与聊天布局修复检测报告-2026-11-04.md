## 本轮实现

1. 注意勾选立即持久化完成状态，原分组原位置保留约 5 秒，可直接取消完成。超时仅移除局部行，旋转继续原单调时钟期限；无障碍采用系统建议超时。`CompletionUndoTicket` 在仓库写入边界校验任务版本，其他任务修改不影响，同任务编辑、删除后拒绝恢复。
2. 待办、详情及 AI 提案显示提醒日期和时间，截止单独标注；支持 `reminderAt`，相对倒计时仍从确认执行后起算。不批量转换旧 `dueAt`。
3. `ReminderCoordinator` 应用级调度与投递，不依赖页面；闹钟携带目标时间，触发重新核对任务、开关、目标及完成状态。相同任务同刻合并提醒，仍执行倒计时推进或日程结束状态转换。升级前历史提醒不会重新投递。
4. 有精确闹钟权限时优先精确调度，权限丢失后降级；系统通知请求横幅、默认声音与震动，保留 `task_reminders` 渠道及用户设置。前台 Material 弹窗合并提醒，不额外播放声音，不自动完成任务。`ReminderEvent` 区分 pending/posted/blocked/failed 与前台呈现记录。
5. 诊断入口提供通知、渠道、声音、震动、精确闹钟、勿扰和后台状态及测试通知。`posted` 仅指已提交系统，不宣称已响铃、震动或展示横幅。
6. 共享气泡字体、行距与内边距；短文字自然收缩，附件按容器宽度布局，文件名两行、大小独立显示。撤销低强调描边，查看安排/进入专注为文字操作，不移出原气泡。
7. `ComposerSubmission` 快照与提交身份保护：发送立即清空已提交内容；准备失败、停止、连接切换、历史聊天切换、重建后丢弃旧回调。未改草稿自动恢复；新草稿不被覆盖，提供恢复入口。消息入历史后不因模型失败重新填回。

不修改任务数据库版本、OAuth、额度接口或凭据。新增 ReminderEvent JSON 字段为向后兼容增量，不升级快照版本。

## 失败与修正记录

- 新 JSON 兼容测试最初放 JVM，因 Android JSONObject stub 未实现而失败，移到真实 Android 仪器测试后通过，未修改生产 JSON 行为来迎合测试。
- 初始布局断言错误要求横屏附件超过半屏，与 320dp 上限冲突；修正为可读宽度断言，保留附件上限。
- 仪器运行中撤销通知权限导致 Android 终止测试进程；AppOps 方式又未真实形成拒绝状态。改为独立进程启动前撤权，断言系统通知确实关闭，测试通过。失败日志保留，不认作业务通过。
- 动效批次首次失败因系统动画前置状态异常；在模拟器显式设置 scale=1 后完整动效通过，scale=0 专项另行通过。原始 scale 未设置，测试结束恢复未设置状态；不改手机动画设置。
- 复查修正旧事件重投递、同刻 schedule_end 状态遗漏、并行投递竞争、附件切换历史聊天/连接时的过期回调，以及旧 focus 广播主线程访问问题。
