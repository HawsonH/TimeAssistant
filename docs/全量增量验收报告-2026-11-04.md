# 时屿全量增量验收报告

日期：2026-11-04，Asia/Shanghai。

11 月 5 日补充：重连手机后，包含导航修正的只读批次已 9/9 通过；测试通知再次进入系统，但静音渠道仍未配置声音/震动。下文保留 11 月 4 日现场状态，后续证据与待验项见《真机补充验收报告-2026-11-05》。

## 范围与保护

- 覆盖当前已实现的任务、周期、专注、聊天提案、设置、教程、连接配置，以及本轮注意缓冲、提醒和附件发送行为。

- 手机本轮展示测试与一条非持久化测试通知不创建任务，不操作真实账号，不调用真实模型、OAuth 或额度服务。`device.qa`、原 QA 和正式版未操作。

## 手机实际结果

机型 PJX110。本轮只读批次 9 项中 8 项通过：专注展示、96 配置气泡绘制、登录帮助和虚构额度；导航用例因异步页面尚未渲染而断言失败。等待时序已修正并在模拟器通过，但手机随后无线断开，未将手机该项改写为通过。

一次测试通知专项 1/1，`full-acceptance-phone-notification.txt`：

| 系统实测项 | 结果 |
| --- | --- |
| 应用通知许可 | 已开启 |
| NotificationManager 中通知存在 | true |
| 已有渠道重要性 | 3，DEFAULT |
| 渠道声音已配置 | false |
| 渠道震动已配置 | false |
| 勿扰过滤器 | 1，ALL，该次检查时未限制 |

测试通知等待 20 秒后撤回，没有写入提醒事件或任务。检查前后既有渠道值一致，未改声音、震动、优先级或勿扰，也未通过新渠道绕过原设置。

现有渠道配置可以解释缺少声音、震动及高优先级横幅的现象，但“系统内通知存在”不是用户实际听见、感到或看见的证据；截至本报告未取得用户观察确认。用户可自行进入“安排偏好与通知 > 任务提醒诊断 > 提醒渠道设置”调整后再测试。最终检查 ADB 仅见模拟器，实体手机后续验收待重新连接。

## 失败、修正与作废取证

1. QA 包标识断言只识别旧包，新增明确允许的交互隔离包，未放开正式版清库保护。
2. 旧聊天测试在文字节点寻找气泡背景；共享气泡背景实际在父容器，改为检查真实容器及其背景，不改变生产布局迎合测试。
3. 导航检查发生在异步 render 前；提醒诊断检查发生在弹窗附着前。分离操作与断言并等待空闲，完整专项复测通过。
4. 通知深链会创建/替换 Activity，旧测试持有的 ActivityScenario 无法继续追踪。改为先关闭原场景、使用真实通知 PendingIntent 冷启动，再通过生命周期监视器检查当前页面及失效链接。
5. 首次横屏采集与后续视觉任务发生测试编排重叠，进程被打断；该次作废，不认定为应用崩溃修复。等待任务结束后单独重跑横屏通过，受影响的两组紫色取证也重新采集。旧日志留在 `history/`。

## 待验与发布门槛

- 手机重新连接后复测修正的只读导航；实际横幅、声音、震动和通知点击需人工观察，手机本轮未做业务提醒到点、锁屏或权限切换。
- 厂商长后台、系统回收、设备重启、精确闹钟真实授权撤销及恢复、勿扰效果尚未本轮验收；API 36 默认具备的精确能力不等于撤权测试。
- TalkBack 手动阅读/操作、所有页面所有尺寸和键盘/动效组合未穷举；局部断言和截图不代替人工可用性检查。
- 不重新验证真实 AI 服务质量、官方账号授权或额度读取，不改变此前真实接口结论。
- 原计划未完成的安全同步、加密备份、双设备和其他模块化事项保持原状态，不因本地测试通过标为完成。
